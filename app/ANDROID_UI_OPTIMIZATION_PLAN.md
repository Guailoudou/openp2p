# OpenP2P Android 前端样式优化方案

> 文档状态：设计与实施建议稿  
> 适用范围：`app/app` Android 客户端  
> 目标技术栈：Kotlin + Android View + Material Components  
> 原则：本轮优先完成体验统一与可维护性改造，不改变 OpenP2P 核心、VPN、管理 API 及业务规则。

## 1. 项目现状

当前主入口为 `cn.openp2p.ui.MainActivity`，页面主要由 Kotlin 动态创建 View，包含：

- 首页：OpenP2P 运行状态、启动/停止、未登录时的 Token 配置。
- 设备：设备列表、编辑、升级、重启、删除、端口映射。
- 网络：SD-WAN 参数、中心节点、中继策略、网络成员。
- 日志：本次运行日志实时展示。
- 我的：管理账号、关于、管理中心 WebView。
- 旧登录页：`LoginActivity` + `activity_login.xml`，目前不是 Launcher 主入口，但仍保留在工程中。

现有界面已经具备基础卡片、按钮、输入框、底部导航和 Bottom Sheet，但视觉与交互仍处于“功能可用”阶段，尚未形成完整的 Android 设计系统。

### 1.1 已发现的主要问题

| 级别 | 问题 | 当前表现 | 用户影响 |
| --- | --- | --- | --- |
| P0 | 中文文本编码异常 | Kotlin 和 `strings.xml` 中存在大量乱码 | 页面不可读，阻断核心操作 |
| P0 | 明暗主题冲突 | 夜间主题使用 `DarkActionBar`，主界面却是 `NoActionBar` 结构；页面颜色大量硬编码为浅色 | 深色模式下标题栏、背景、文字和系统栏不一致 |
| P0 | 关键操作状态不完整 | 启停、登录、保存、升级等主要依赖 Toast，按钮缺少进行中/成功/失败状态 | 用户容易重复点击，不清楚操作是否完成 |
| P1 | 设计令牌缺失 | Kotlin 内硬编码颜色、字号、圆角、间距，资源文件只定义少量颜色与尺寸 | 风格难统一，后期维护成本高 |
| P1 | 导航图标状态不清 | Vector 图标写死为蓝色，同时关闭 `itemIconTintList` | 选中与未选中项区分弱 |
| P1 | 信息层级不足 | 状态、说明、属性和操作大多堆叠在同一种白色卡片中 | 扫读效率低，重要信息不突出 |
| P1 | 隐蔽手势承载核心功能 | 设备操作通过长按卡片打开菜单 | 可发现性差，不利于新用户与无障碍用户 |
| P1 | 列表与空态过于简单 | 设备、成员、映射为空时仅展示一行文字；加载和错误没有独立页面状态 | 缺乏下一步引导，也难区分“空”与“加载失败” |
| P1 | 旧页面固定尺寸 | `activity_login.xml` 使用 250dp、359dp、548dp 等固定宽高 | 小屏溢出、大屏留白、横屏不可用 |
| P2 | 内容直接写在代码中 | 大量 UI 文案未进入字符串资源 | 无法可靠国际化，也容易再次产生编码问题 |
| P2 | Token 暴露风险 | 账号信息可能直接显示完整 Token | 肩窥、截图和录屏时泄露凭据 |
| P2 | WebView 弹层体验弱 | 管理中心固定为约 78% 屏幕高度，缺少加载、错误、返回和外部打开能力 | 页面导航与异常恢复不清晰 |

## 2. 优化目标

### 2.1 体验目标

1. 用户进入首页后 3 秒内理解当前是否运行、是否已配置，以及下一步该做什么。
2. 设备在线状态、版本状态和高风险操作可以被快速识别。
3. 所有网络配置均遵循“查看—编辑—校验—保存—反馈”的一致流程。
4. 所有页面覆盖加载、内容、空、错误、离线和无权限状态。
5. 浅色、深色、系统字体放大、横屏和常见平板宽度下均可正常使用。

### 2.2 工程目标

1. 消除 UI 层硬编码颜色、文案和主要尺寸。
2. 建立可复用的页面标题、状态卡、属性行、按钮、空态和 Bottom Sheet 组件。
3. 保留现有 Android View 技术栈，先完成低风险重构，不在本轮强制迁移 Jetpack Compose。
4. 不修改 VPN 服务、管理 API、登录状态和核心运行逻辑。

## 3. 视觉方向

视觉关键词：**可靠、清晰、轻量、网络感**。

- 品牌蓝继续作为主色，但减少大面积高饱和填充，主要用于主按钮、焦点、选中状态和链接。
- 页面采用中性灰背景与分层表面，运行状态用蓝/绿辅助表达，不只依赖颜色。
- 设备、IP、端口、版本、日志等技术信息使用等宽数字特性或等宽字体，提高对齐与扫读效率。
- 卡片减少阴影，主要依靠 1dp 描边、背景层级和合理留白分组，避免“所有内容都是悬浮卡片”。
- 动效保持克制：状态切换 150–250ms，加载使用骨架或进度指示，避免无意义装饰动画。

## 4. 设计系统

### 4.1 颜色令牌

以下为建议值，实施时统一落入 `colors.xml` 和 `values-night/colors.xml`，业务代码只引用语义名称。

| 令牌 | 浅色模式 | 深色模式 | 用途 |
| --- | --- | --- | --- |
| `brand_primary` | `#0A59F7` | `#8CB4FF` | 主按钮、选中态、链接 |
| `brand_on_primary` | `#FFFFFF` | `#002D6A` | 主色上的文字/图标 |
| `surface_page` | `#F5F7FA` | `#101318` | 页面背景 |
| `surface_card` | `#FFFFFF` | `#191D24` | 卡片、弹层 |
| `surface_subtle` | `#EEF3FA` | `#222832` | 次级区域、标签背景 |
| `border_default` | `#E3E8EF` | `#343B47` | 卡片和分隔线 |
| `text_primary` | `#182431` | `#F1F4F8` | 标题、正文 |
| `text_secondary` | `#637083` | `#AAB3C0` | 说明、元数据 |
| `state_success` | `#16855B` | `#5DD6A5` | 在线、成功、运行中 |
| `state_warning` | `#B86700` | `#FFB95C` | 可升级、需注意 |
| `state_error` | `#C9362B` | `#FF8A80` | 失败、删除、离线异常 |
| `state_info` | `#0A59F7` | `#8CB4FF` | 信息提示、进行中 |

要求：

- 正文与背景对比度至少 4.5:1，大字号至少 3:1。
- 在线/离线、成功/失败除颜色外，必须同时使用文字、图标或形状。
- Vector Drawable 使用主题色或 tint selector，不在 path 中写死品牌蓝。

### 4.2 字体层级

| 样式 | 建议规格 | 用途 |
| --- | --- | --- |
| Page title | 28sp / Medium | 一级页面标题 |
| Section title | 18sp / Medium | 区块标题 |
| Card title | 16sp / Medium | 卡片主标题、设备名 |
| Body | 14sp / Regular | 常规正文 |
| Label | 13sp / Medium | 字段名、状态标签 |
| Caption | 12sp / Regular | 版本、IP、帮助信息 |
| Mono | 12–14sp / Monospace | 日志、Token、IP、端口 |

所有文字使用 `sp`，允许系统字体缩放；重要信息不得通过缩小字号强行塞入一行。

### 4.3 间距、圆角与触控

- 基础间距单位：4dp。
- 页面水平边距：手机 16dp；宽屏 24–32dp。
- 区块间距：24dp；卡片间距：12dp；卡片内边距：16dp。
- 卡片圆角：16dp；输入框/按钮：12dp；状态胶囊：999dp。
- 标准按钮高度：48dp；主操作按钮可使用 52dp。
- 所有可点击区域至少 48dp × 48dp。
- 页面底部内容需要计入底部导航和手势区 Insets，避免最后一个按钮被遮挡。

### 4.4 通用组件

建议将当前 `UiKit.kt` 拆分或扩展为以下复用组件：

| 组件 | 说明 |
| --- | --- |
| `AppPage` | 统一处理系统栏、标题、滚动容器、内容边距和宽屏最大宽度 |
| `StatusHeroCard` | 首页运行状态、状态图标、说明和主操作 |
| `SectionHeader` | 区块标题、数量、可选右侧操作 |
| `InfoCard` | 通用分组容器，支持标题、说明、描边和点击态 |
| `KeyValueRow` | 账号、版本、IP、端口等属性展示 |
| `StatusChip` | 运行中、已停止、在线、离线、可升级、异常 |
| `PrimaryButton` | 主操作，内置 loading/disabled 状态 |
| `SecondaryButton` | 次操作或描边按钮 |
| `DestructiveButton` | 删除、移除、退出等危险操作 |
| `AppTextField` | 统一标签、帮助信息、错误信息、密码显示切换和 IME |
| `EmptyState` | 图标、标题、说明和可选 CTA |
| `ErrorState` | 简短原因、重试按钮、可选详情 |
| `LoadingState` | 首屏骨架/进度与刷新状态 |
| `AppBottomSheet` | 圆角、拖拽柄、标题、滚动、固定操作区和 Insets |
| `ConfirmDialog` | 对升级、重启、删除、退出提供分级确认 |

## 5. 信息架构与导航

### 5.1 底部导航

保持现有五类信息架构，但统一导航策略：

- 未登录：`首页 / 日志 / 我的`。
- 已登录：`首页 / 设备 / 网络 / 日志 / 我的`。
- 图标必须具备选中和未选中颜色；选中项使用品牌蓝并显示文字，未选中使用 `text_secondary`。
- 导航高度遵循 Material 组件默认值并通过 Insets 扩展底部安全区，不写死 68dp 总高度。
- 切换登录态重新构建菜单时保留合理的当前页；若当前页被移除，返回“我的”并给出简短说明。
- 保留各 Tab 的滚动位置和加载数据，避免每次切换都重建页面和重复请求。

### 5.2 页面层级

- 一级页：使用大标题与内容区。
- 编辑、新增、详情：优先使用全高 Bottom Sheet；字段超过 6 个或包含复杂依赖时改为独立页面。
- 短确认：Dialog。
- 轻量反馈：Snackbar；只有无需撤销且不影响当前任务的瞬时提示才使用 Toast。

## 6. 逐页优化方案

### 6.1 首页

首页首屏围绕“连接状态”组织，不再用普通卡片平铺。

建议结构：

1. 顶部标题 `OpenP2P`，右侧可放帮助入口。
2. 运行状态 Hero 卡：
   - 状态图标 + `运行中 / 正在启动 / 已停止 / 连接异常`。
   - 一行可理解的状态说明，不直接把底层原始状态作为唯一文案。
   - 主按钮 `启动 OpenP2P` 或 `停止 OpenP2P`。
   - 启动/停止过程中按钮显示进度并禁用重复点击。
3. 配置概览：Token 来源、VPN 授权状态、管理账号状态。
4. 未配置引导：说明 Token 的用途，提供 `配置 Token` 和 `登录管理账号` 两条路径。
5. 常见问题入口：后台运行、电池优化、VPN 权限，不在首页铺陈长篇说明。

状态规范：

- 已停止：中性灰，不使用错误红。
- 正在启动/连接：蓝色进度状态。
- 运行中：绿色状态 + “连接已建立”。
- 异常：红色状态 + 简短原因 + `重试`/`查看日志`。

### 6.2 Token 配置与账号登录

- Token 输入默认按密码处理，仅显示末 4 位，提供显隐按钮和粘贴按钮。
- 数字键盘只是输入优化，不能代替服务端/本地格式校验。
- 保存成功后使用 Snackbar，并在首页配置概览中立即更新。
- 管理账号登录按钮具备 loading 状态，失败信息显示在表单内，不仅使用 Toast。
- 明确区分“本地 Token 模式”和“管理账号模式”，说明登录后会同步 Token 并开放设备/网络页面。
- 已登录账号详情中 Token 默认遮罩，提供显式 `复制` 操作；复制后提示凭据敏感。

### 6.3 设备页

列表顶部增加：

- 页面标题与设备总数。
- 在线/离线筛选 Chip；设备较多时增加搜索。
- 下拉刷新保留，但首屏加载使用独立 loading 状态。

设备卡片结构：

- 第一行：设备名称 + `在线/离线/异常` 状态 Chip + 更多菜单按钮。
- 第二行：系统图标、系统类型、版本；存在新版本时显示 `可升级` Chip。
- 第三行：局域网 IP、公网 IP，允许长按复制。
- 卡片点击打开设备详情；右上角显式“更多”按钮承载编辑、端口映射、升级、重启、删除，长按仅作为可选快捷方式。

高风险操作：

- 升级：确认框展示当前版本、目标版本、可能中断时间。
- 重启：明确连接会暂时中断。
- 删除：危险色按钮，确认框展示设备名；必要时要求二次确认。
- 操作提交后对对应设备卡显示局部进度，完成后刷新，避免全页无反馈。

空态文案建议：`还没有设备` + `登录管理中心并添加设备后，会在这里集中管理。` + `打开管理中心`。

### 6.4 端口映射

- 映射列表以协议 Chip、源端口、目标设备/地址/端口形成明确的连接关系。
- 启用状态使用 Switch 或状态 Chip，不再让“启用/停用”与“编辑/删除”混在三个等权按钮中。
- 新增/编辑表单按以下区块分组：基本信息、源端、目标端、高级选项。
- TCP/UDP 使用 Segmented Button 或单选组；远端设备、中继节点使用 Exposed Dropdown，不使用 `NumberPicker`。
- 端口范围实时校验为 1–65535；IP/域名、白名单显示格式说明与字段级错误。
- `检测远端服务` 为次按钮，结果在按钮下方以内联状态展示。
- 保存按钮固定在 Bottom Sheet 底部；内容可滚动，键盘弹出后按钮仍可见。

### 6.5 网络页

拆分为“网络概览”和“成员管理”两部分：

- 概览卡显示网络地址、模式、成员数、健康状态。
- `编辑网络配置` 打开独立 Bottom Sheet，避免配置表单长期占据首屏。
- 全互联/中心节点使用有说明的选择卡或 Segmented Button。
- 只有选择中心节点模式时才显示中心节点字段，并解释其作用。
- 强制中继属于高级设置，默认折叠；打洞优先级使用下拉选项并配说明。
- 成员列表显示设备状态、虚拟 IP、资源，点击进入成员编辑。
- 加入设备时先判断可用设备为空，给出原因：设备离线、版本低于 3.13 或已加入网络。
- 网络地址、虚拟 IP 提供格式校验和冲突检测，错误显示在字段下方。
- 未保存修改退出时给出放弃确认；保存时展示进度，并说明正在刷新在线节点。

### 6.6 日志页

- 顶部提供日志级别筛选、自动滚动开关、清空视图、复制和分享/导出入口。
- 日志区使用等宽字体、可选择文本、稳定的行距和深浅主题背景。
- 新日志到达时，如果用户停留在底部则自动滚动；用户已向上查看时不抢夺位置，并显示“回到底部”按钮。
- 不每秒替换整个 TextView 内容；实施时采用增量更新或适合长文本的列表方案，降低长日志卡顿。
- 空态：`本次启动暂无日志`；错误日志可使用低强度色彩标识，避免整行高饱和红色。
- 分享或复制前考虑对 Token、账号等敏感字段做脱敏。

### 6.7 我的

建议分组：

1. 账号卡：头像占位、账号名、登录状态；点击进入账号详情。
2. 服务与支持：管理中心、后台运行设置、使用帮助。
3. 应用：外观、关于、版本信息、开源许可。

交互建议：

- 每一项使用 56dp 以上设置行，包含图标、标题、可选说明和尾部箭头。
- 退出登录放在账号详情底部，以危险色文字按钮呈现，不与普通主按钮同级。
- 关于页展示应用版本、构建号、官网与开源仓库；不只展示一句简介。
- 管理中心优先考虑 Custom Tab 或外部浏览器；若继续使用 WebView，必须补充加载进度、错误页、返回历史、外部打开和关闭按钮。

### 6.8 旧 `LoginActivity`

先确认它是否仍被外部 Intent、历史流程或测试依赖：

- 若无依赖：移除 Activity、布局和对应 ViewModel，避免维护两套启动流程。
- 若必须保留：完全重做为响应式单列页面，使用 Material 输入框和按钮，移除固定宽高和超长不可编辑 EditText；后台运行说明改为分品牌折叠的帮助页。
- 无论是否保留，都应修复字符串编码，并避免页面内部无限线程和强制退出流程影响体验。最后两项属于交互关联的工程风险，应单独评审，不在纯样式提交中顺手修改。

## 7. 全局页面状态

每个异步页面至少覆盖以下状态：

| 状态 | 表现 | 可执行动作 |
| --- | --- | --- |
| 首次加载 | 骨架或居中进度，不展示错误空态 | 等待/取消（如适用） |
| 下拉刷新 | 保留已有内容，顶部刷新指示 | 继续浏览 |
| 内容 | 正常列表或配置 | 查看/编辑 |
| 空 | 图标、说明、下一步 CTA | 添加/打开管理中心 |
| 网络错误 | 简短原因，不清空可用旧数据 | 重试/查看详情 |
| 登录失效 | 解释会话失效 | 重新登录 |
| 无 VPN 权限 | 解释权限用途 | 去授权 |
| 提交中 | 当前按钮或行内进度，防止重复提交 | 等待 |
| 提交成功 | Snackbar 或页面内成功状态 | 可选撤销 |
| 提交失败 | 字段错误或 Snackbar，保留输入 | 重试 |

## 8. 深色模式、系统栏与响应式

### 8.1 深色模式

- `values/themes.xml` 与 `values-night/themes.xml` 使用相同的 NoActionBar 父主题结构。
- 所有背景、文字、描边、状态色来自主题属性或语义资源，移除 Kotlin 中的 `Color.WHITE` 等固定颜色。
- Bottom Sheet、Dialog、PopupMenu、WebView 容器和底部导航全部验证深色主题。
- 启动页、状态栏、导航栏图标明暗随主题切换。

### 8.2 响应式

- 紧凑宽度（< 600dp）：单列布局，底部导航。
- 中等/展开宽度（≥ 600dp）：内容最大宽度建议 720–840dp 并居中；设备/成员列表可双列，或使用 Navigation Rail。
- 横屏时标题区域收紧，复杂编辑表单允许双列字段，但保持自然阅读顺序。
- 不使用固定页面宽高；列表、表单和 WebView 由约束、权重和 Insets 决定尺寸。

## 9. 无障碍与易用性

- 图标按钮设置明确的 `contentDescription`，纯装饰图标标记为不参与无障碍。
- TalkBack 顺序与视觉顺序一致；卡片中的多个操作可分别聚焦。
- 支持至少 200% 字体缩放，不裁切标题、按钮或状态文字。
- 不以长按作为唯一入口，不以颜色作为唯一状态表达。
- 输入框配置正确的键盘类型、IME Action、自动填充和错误播报。
- 动态状态变化通过可访问性公告适度播报，例如“OpenP2P 已启动”。
- 点击区域至少 48dp，重要控件之间保持足够距离。
- 动效遵循系统“移除动画”设置，避免持续闪烁和快速颜色变化。

## 10. 文案规范

- 所有用户可见文字迁移到 `res/values/strings.xml`，中文放入 `res/values-zh-rCN/strings.xml`；源文件统一 UTF-8。
- 状态文案用用户语言，例如“正在连接”，底层状态码仅放在详情或日志中。
- 按钮使用“动词 + 对象”：`保存网络配置`、`添加设备`、`复制 Token`。
- 危险操作明确结果：`删除设备`、`移出网络`，不使用含糊的“确定”。
- IP、VPN、SD-WAN、Token 等术语首次出现可配一行简短说明。
- 避免同一概念混用“登录/启动”“网络/组网”“设备/节点”等称呼。

## 11. 技术落地与文件建议

本方案建议继续使用现有 View 体系，优先整理资源和组件；Compose 迁移可在后续单独评估，不作为视觉优化前置条件。

| 文件/目录 | 建议调整 |
| --- | --- |
| `res/values/colors.xml` | 改为语义颜色令牌 |
| `res/values-night/colors.xml` | 新增完整深色颜色映射 |
| `res/values/themes.xml` | 统一 NoActionBar、控件样式、系统栏配置 |
| `res/values-night/themes.xml` | 与浅色主题保持同结构，仅替换主题属性 |
| `res/values/dimens.xml` | 增加页面、卡片、控件、宽屏尺寸令牌 |
| `res/values/styles.xml` | 增加按钮、输入框、状态 Chip、文本外观样式 |
| `res/values/strings.xml` | 保留默认语言并修复编码 |
| `res/values-zh-rCN/strings.xml` | 集中维护简体中文文案 |
| `res/color/` | 新增导航、按钮、图标、文本的状态 selector |
| `res/drawable/` | 替换写死颜色的导航图标，补充状态与空态图标 |
| `ui/UiKit.kt` | 从硬编码工具函数升级为主题感知组件，必要时拆为 `components/` |

实施约束：

- 先确认现有未提交修改的意图，逐文件合并，不能覆盖当前业务开发。
- 样式重构期间不改变 API 请求参数、VPN 启停语义、设备版本判断和 SD-WAN 规则。
- 如果升级 Material Components、compileSdk 或 targetSdk，必须作为独立工程任务评估兼容性，不能夹在纯 UI 提交中。
- 保持 `minSdkVersion 16` 时，对仅高版本可用的窗口与系统栏 API 做版本保护。

## 13. 验收标准

### 13.1 视觉与交互

- [ ] 所有页面无乱码、无截断、无重叠。
- [ ] 浅色与深色模式均无白底白字、黑底黑字或错误 ActionBar。
- [ ] 底部导航有明确选中态，图标不再写死为同一蓝色。
- [ ] 首页四种核心状态（停止、启动中、运行、异常）表现完整。
- [ ] 设备、映射、网络成员均有加载、空、错误和内容状态。
- [ ] 所有提交按钮有 loading 与防重复点击能力。
- [ ] 删除、重启、升级、退出等高风险操作有清晰确认。
- [ ] Token 默认脱敏，不在普通页面直接完整暴露。
- [ ] Snackbar、字段错误和 Dialog 的使用符合反馈层级。

### 13.2 适配与无障碍

- [ ] 360×640dp 小屏无横向溢出。
- [ ] 常见全面屏手势导航下内容不被系统栏遮挡。
- [ ] 600dp 及以上宽度不会无限拉伸，列表或内容合理利用空间。
- [ ] 横屏可完成登录、网络配置和端口映射编辑。
- [ ] 系统字体 200% 时核心内容和按钮仍可用。
- [ ] TalkBack 可读出导航、状态、表单错误与图标按钮含义。
- [ ] 所有主要触控目标不小于 48dp。

- [ ] 本地 Token 保存、VPN 授权、启动和停止行为不变。
- [ ] 管理账号登录/退出及导航显隐行为不变。

- [ ] 端口映射增删改、启停、检测行为不变。
- [ ] SD-WAN 保存、节点刷新、成员增删改行为不变。
- [ ] 日志采集内容与服务运行不受 UI 重构影响。
